# Корпорация Стальконструкция

Многостраничный сайт на React 19, TypeScript и Vite. Дизайн сохраняет Precision Blueprint исходного лендинга. При сборке каждая страница получает самостоятельный HTML с содержимым, метаданными и хлебными крошками; клиентский JavaScript добавляет меню и формы.

## Разработка и проверка

```sh
npm ci
npm run dev
npm run build
npm test
npm run test:browser
npm run preview
```

В `vite dev` и `vite preview` нет Netlify Functions. Полная локальная проверка функции — через `netlify dev`. Для просмотра формы без настроенных получателей отправка отключена с явным сообщением. Автотесты функции используют подменённые API и никому не отправляют сообщения.

Для браузерных проверок установите тестовый браузер через `npx playwright install chromium` или задайте путь к существующему Chromium в `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Playwright сам поднимает сервер предпросмотра. Перед `npm test` и браузерными проверками выполните сборку.

## Содержание

22 страницы: главная, о компании, продукция, проектирование, комплексная поставка, монтаж, производство, проекты, блог, контакты, отраслевой каталог, 9 отраслевых страниц и 2 страницы с текстами об обработке данных. Дополнительно — настоящая 404, sitemap.xml и robots.txt.

Новый источник: «Содержание сайта (Структура) (2).docx» и решения владельца от 02.11.2026. Пункт 9 продукции — «Другие отрасли», пункт 10 — самостоятельный раздел `/produkciya/#po-chertezham`. Старые материалы проекта применены там, где они не противоречат новому ТЗ. Кейсы и статьи не выдумываются. На главной пустые тизеры проектов и блога убраны, страницы созданы.

## Заявки с вложениями

`netlify/functions/inquiry.mjs` принимает multipart-заявку на `/api/inquiry` и передаёт данные вместе с файлами в email через Resend и Telegram Bot API. Перед запуском задайте в настройках Netlify пять серверных переменных из `.env.example`: `RESEND_API_KEY`, `INQUIRY_EMAIL_FROM` (адрес на подтверждённом домене отправителя), `INQUIRY_EMAIL_TO`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Бот должен иметь право отправки в выбранный чат. Не передавайте токены в клиентские переменные `VITE_*` и не коммитьте `.env`.

Оба канала должны быть настроены. Успех подтверждается только после доставки полного обращения хотя бы в один канал; ошибки другого фиксируются по номеру заявки без персональных данных. Для email используется ключ идемпотентности. Telegram не гарантирует защиту от дублей при потере ответа; одинаковые номера позволяют распознать повтор. Контекст страницы, направление, согласие и файлы входят в обращение.

Лимит: до 5 файлов и 3 МБ суммарно. Он выбран с запасом под [ограничение буферизованного запроса Netlify](https://docs.netlify.com/build/functions/configuration/) с кодированием двоичных данных. Для больших комплектов в форме можно указать ссылку. Форматы: PDF, DWG, DXF, DOC/DOCX, XLS/XLSX, ZIP, JPG/PNG. Вложения передаются провайдерам, на сайте не публикуются; проверки формата основаны на расширении, получатель должен проверять файлы перед открытием.

Функция проверяет размер тела до разбора multipart, размеры полей, контакт, согласие, имя файла, количество и общий объём вложений, origin и honeypot. Rate limit Netlify — 30 запросов за минуту по IP и домену, включая проверку доступности формы. Описание API: [Netlify Functions](https://docs.netlify.com/build/functions/api/), [Resend](https://resend.com/docs/api-reference/emails/send-email), [Telegram Bot API](https://core.telegram.org/bots/api#senddocument).

## Перед публичным запуском

Замените помеченные тестовые контакты в `ContactsPage` и `Footer`; подтвердите адрес посещения и режим работы. Страницы политики и согласия содержат рабочие черновики: оператор должен утвердить тексты и контакт для обращений до включения формы. Укажите итоговый `SITE_URL`. Для индексации задайте `SITE_INDEXABLE=true` и пересоберите сайт; до этого страницы имеют noindex, robots.txt закрывает обход. Черновые юридические страницы всегда noindex. Материалы портфолио и статьи добавляются по готовности.

Сборка не меняет опубликованный сайт. Netlify использует `npm run build`, каталог `dist` и функции из `netlify/functions`.

## Последние правки

После ревью исправлены контраст мелких подписей, повторная проверка доступности формы с тайм-аутом 8 секунд и блок четырёх преимуществ комплексной поставки по образцу ТЗ. Повторная проверка не очищает поля и вложения. Контакты и серверная доставка заявок не менялись.

Адаптивные WebP, мобильный кроп первого экрана и уменьшенный знак в шапке находятся в `public/media`; имена включают хеш содержимого. Исходники сохранены. Для обновления вариантов после замены исходных изображений выполните `python3 scripts/optimize-images.py` (требуется Pillow), затем обычную сборку. Реестр вариантов — `src/data/images.ts`. Нижнее фото производства загружается отложенно. Vite складывает хешированные JS/CSS в `/build/`; годовой immutable-кэш применяется только к `/build/` и `/media/`, постоянные URL `/assets/` проходят перепроверку.

На главной убрана подпись «Состав продукции» с отраслевых карточек. Производство, проекты и блог сгруппированы в меню «О компании», мобильной навигации, подвале, ссылках страницы компании и хлебных крошках. URL страниц сохранены.

Девять отдельных светлых иллюстраций отраслей созданы ImageGen на основе референсов stalkonstrukciya-web.netlify.app и тематических сцен. Они не представлены как фотографии реализованных объектов. PNG-оригиналы находятся в `design/industry-images`, web-версии 1280/640 px — в `public/assets/industries`. Для выбора размера используется srcset.

Контакты в шапке настраиваются в `src/data/contacts.ts`: телефон, email, ссылки Max и Telegram и флаг `demo`. Пока данные тестовые, телефон и email показаны текстом, кнопки мессенджеров недоступны и не ведут к посторонним профилям. В мобильном меню доступны те же контакты. Иконки взяты из `/icons/` согласованного референса stalkonstrukciya-web.netlify.app.
